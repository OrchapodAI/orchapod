## Friction points, worst first

**P0. `make up` fails on a clean Docker: the MinIO image is gone** (README 112; `infra/docker-compose.dev.yml:41`, also `infra/docker-compose.smoke.yml:18`).
- What happened: nothing failed here (image cached). Registry evidence, all metadata calls: Docker Hub's anonymous token for `minio/minio` has an empty `access` list (redis and postgres tokens carry `pull`); `GET hub.docker.com/v2/repositories/minio/minio/` is 404 `object not found`; `docker manifest inspect minio/minio:latest` and a pinned `RELEASE.2025-04-22T22-12-26Z` answer `denied: requested access to the resource is denied`; `docker buildx imagetools inspect minio/minio:latest` answers `pull access denied, repository does not exist or may require authorization: server message: insufficient_scope: authorization failed`; `quay.io/api/v1/repository/minio/minio` is 401; `bitnami/minio:latest` has no manifest. Every other external base image (python:3.12-slim and -trixie, both llama.cpp tags, node:22-alpine, pytorch, nvcr, docker cli) resolves anonymously.
- Effect on a judge: `docker compose up -d postgres redis minio` cannot pull minio, so no storage; the e2e preflight says "MinIO is not reachable ... run `make up`" and the app cannot store artifacts. Not reproduced end to end: pulling would risk retagging the shared image under the running stack.
- Smallest fix (platform): change the `image:` in both compose files to an S3 server that still pulls, then prove it with `make check E2E=1` and `make ui-smoke` on a Docker that lacks the cached image. Candidates whose manifests read anonymously today (not run, not verified): `cgr.dev/chainguard/minio`, `pgsty/minio` (community fork), `bitnamilegacy/minio`, `rustfs/rustfs`, `chrislusf/seaweedfs`, `ghcr.io/versity/versitygw`, `zenko/cloudserver`, `adobe/s3mock`. Check that the compose healthcheck's `curl` exists in the new image. No third party needed: push the image already running (`sha256:14cea493d9a3...`, created 2025-09-07) to `ghcr.io/bangadpurva/minio` and make that package public with the others at G3 (AGPL redistribution is the Orchestrator's call). Needs the human's choice: third-party image.

**F1. pnpm 11 breaks the Setup code block** (README 137-138; the workaround is prose at 141).
- What happened: `pnpm install` installs everything, then exits 1: `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: sharp@0.34.5`. The next line, `pnpm dev`, re-runs install through pnpm's dependency check and dies with `Command failed with exit code 1: pnpm install` and a JavaScript stack trace; nothing starts. pnpm 11 is current (11.0.9 here), so this is the normal case for a new install.
- Smallest fix (devrel): put the working pair in the code block: `pnpm install  # pnpm 11 exits 1 on ERR_PNPM_IGNORED_BUILDS: sharp; harmless` then `pnpm --config.verify-deps-before-run=false dev` (tested: starts). Verified alternative that removes the error at the source on pnpm 11: `apps/web/pnpm-workspace.yaml` containing `allowBuilds:` / `  sharp: false` (the file is gitignored on purpose, it broke pnpm 9 CI once): install then exits 0 and a plain `pnpm dev` starts. Tested and useless on pnpm 11: `package.json` `pnpm.ignoredBuiltDependencies` (still exit 1); `.npmrc`'s `allow-build=sharp` has no effect. pnpm 9 not tested.

**F2. API port 8001 is hard-coded and the README never says how to move it** (README 134; `.env.example:43`; web default in `apps/web/next.config.ts`).
