## Fix round 1 (review verdict "Needs fixes"; the Orchestrator's rulings)

- **I1, the limit.** `LIVE_LIMIT_S = 7200` for the golden run only; `REAL_LIMIT_S` stays 3600 for intents 1 to 3. The healthy worst case is
  75 to 87 minutes, and every paid resource has a server-side stop of its own (R14's spend deadline, the Job's 3600 s, the endpoint's
  TTL), so an hour protected nothing and risked cancelling a run that was going well. The estimate refusal follows it (120 minutes).
- **I2, the polls.** The "15 failed polls, then cancel" give-up is gone. A poll that fails (no answer, a 5xx, a 2xx that is not JSON) is
  asked again until the limit, with a warning at most once a minute (one line, whatever the error page holds); a 3xx or 4xx never heals, and
  is raised. The only cancels are at the limit, on Ctrl-C and on SIGTERM, two attempts each, each announced with
  `cancelling run <id> (up to 90 s)`. A cancel that fails, or any other way out while the run lives, prints
  `run <id> may still be running; cancel it as the admin: curl -X POST -H "X-Orchapod-Admin: $ORCHAPOD_ADMIN_TOKEN" https://<host>/runs/<id>/cancel`:
  the variable, never its value, and the host without any userinfo. The server's caps bound the spend. If no poll ever answered, the
  verdict is a FAIL ("the run was not seen once in 7200 s, so it was cancelled").
- **I3, the evidence.** The endpoint's `expires_at` line comes first, and the summary is read under `except Exception`: an unreadable one (a
  500, a 200 that is not JSON, a shape off the contract, dollars that are not numbers) says so, and a PASS stays a PASS (exit 0).
- **M1.** A token that is not printable ASCII is refused in one line, value not shown (the environment cannot hold a NUL, so that case is
  tested on `refusal()`; a newline, a tab, DEL and a non-ASCII letter go through `main`).
- **M2.** `call` treats a 3xx, and a 2xx whose body is not JSON, as an error, so `POST /agent/run` answers "the run may have started" for
  those and for a 5xx or a lost reply; an interrupt (Ctrl-C, SIGTERM) during that POST says the same and cancels nothing, since there is
  no token yet. A 4xx is a refusal and says no such thing.
- **M3.** The cancel is announced before each POST; Ctrl-C and SIGTERM make two attempts like the limit, so a first POST that times out
  while the cancel goes through is followed by a second that meets the 409 of a run that has ended ("run <id> had ended"). A redirected
  cancel (a 3xx) is not a cancel.
- **M4.** Section G below (third line, `caffeinate`) and section E (the preflight does not prove the token).
- Also: the output check in `live()` catches `Exception` (a KeyError from a reply off the contract is a FAIL with its evidence, not a
  traceback). The old `TOLERATE_POLLS` and its tests are gone; `poll_run(tolerate=)` is a flag now.

## What it is

`make e2e API=https://api.<domain> [MAX_COST=3]`, which is `python scripts/e2e_demo.py --max-cost 3 --api https://api.<domain>` with
`ORCHAPOD_ADMIN_TOKEN` in the shell. It starts nothing of its own (no Docker, no local API, none of your keys). It reads template 4
(`nebius-docs-specialist`) from the hosted API, starts it as the admin, watches it for at most two hours, checks it, and prints the evidence.
The module docstring is the spec; this is the short form.

- **Refused, one line each, exit 2, before any request:** no `--max-cost`, or one at or under 0 (nan too) or over $3; no `--api`, or one
  that is not https with a host; no `ORCHAPOD_ADMIN_TOKEN` (blank counts as unset, as in `budget.admin`), or one that is not printable
  ASCII; `--stub` with `--api`. **After one `GET /agent/templates`, before anything starts:** the template is not served, has lost the
  golden shape (research, synth, prep, unsloth-train, vllm-serve, judge-eval), its full estimate is over `--max-cost`, or it takes more
  than the two hours the run waits. (The estimate refusal needs a read, so "before any request" is "before any request that starts or spends".)
- **Flow:** `POST /agent/run {intent, plan}` with the template as served and `X-Orchapod-Admin`; keep `cancel_token`; poll
  `/agent/runs/{id}/report` every 2 s until `ready`, at most `LIVE_LIMIT_S` = 7200 s, then `POST /runs/{id}/cancel` with the token, twice if
  the first fails.
- **Checks (e2e_agent's, not copies):** `check_report` (run succeeded, `0 < cost_usd <= --max-cost`, each node's contract artifacts and
  a cost_json, unsloth-train registered `lora_adapter`, the report names the plan) and `check_outputs` (the data-prep rows download,
  judge-eval's `eval_summary` has the contract's shape and `stub: false`); plus the new `check_endpoints`: vllm-serve registered an
  `endpoint_url` that is https and whose `endpoint_id` is not `stub-*`.
- **Output:** the run id is on the third line; e2e_agent's PASS/FAIL line, with `; eval <node>: n, judged, win_rate, exact_match`; the
  endpoint's `expires_at`; each node's status, wall time and $ from `/runs/{id}/summary` and the run's span against G1's 25-minute bar
  (shown, not a check). Exit 0 PASS, 1 FAIL or error, 2 refused.

Beyond the brief, because this is the one command that rents GPUs (decisions below):
- **A run nobody watches is cancelled; one that is left says how to stop it.** Ctrl-C and SIGTERM cancel the run with its token (two
  attempts), then re-raise. A cancel that fails, or any other way out while the run lives (a poll the API refuses), prints the run id and
  the admin's curl. A poll that fails is waited through to the limit. `poll_run` gained `tolerate` (default False, so the stub runs are
  unchanged); `cancel_run` is shared and tries twice; `call` raises `ApiError(status)`, still a `RuntimeError`.
- **A reply to `POST /agent/run` that never came, is a redirect or a 5xx or is no JSON, or an interrupt during that POST, says "the run may
  have started" and how to find it.** A 403 says to check `ORCHAPOD_ADMIN_TOKEN`.
- **Everything printed during the run is scrubbed** of the token and the URL's userinfo (as written and percent-decoded), on stdout and
  stderr, by one wrapper around the whole run; refusals never echo either by construction. The admin header is per request on
  `POST /agent/run` only: a download is a 307 to object storage, and httpx forwards custom headers across hosts (0.28: only
  `Authorization` is dropped).
- **A summary or an output that cannot be read does not change the verdict or hide the evidence.** A URL httpx cannot parse is a one-line
  failure before any request, not a traceback.

## Decisions (Orchestrator: record as DECISION)

1. The live golden run is `make e2e API=https://api.<domain> [MAX_COST=3]`; the admin token comes from the env only and goes out on
   `POST /agent/run` only. Who runs it on G2 day is the Orchestrator's call (CLAUDE.md says "QA agent only").

## Concerns

- **Nothing here has met a real hosted API.** The fake follows the code I read (`routes/agent.py`, `routes/runs.py`, `routes/internal.py`,
  `services/budget.py`, contracts), not a live reply. The first live run may differ in a detail (timestamp format, the endpoint's `uri`).
  The checks fail loudly rather than skip, so a mismatch shows up as a named problem, not a pass.
- **`--max-cost` is the operator's cap, not the server's.** It refuses on the estimate before and fails on `cost_usd` after; while the run
  goes, the caps that stop it are the hosted API's (`ORCHAPOD_MAX_RUN_USD` 3, `ORCHAPOD_MAX_DAY_USD`, the node budgets, the Job's one-hour
  timeout, the endpoint's TTL). A cost only appears when a node's `cost_json` lands (the GPU's bill at pod teardown), so a mid-run
  cancel on `cost_usd` would fire late; I did not add one. To make the server enforce a lower number, set the VM's `ORCHAPOD_MAX_RUN_USD`.
- **A Mac that sleeps stops the polling.** Run it as `caffeinate -i make e2e API=...`. An API that is down for the whole run is polled to
  the limit (a warning a minute), then two cancel attempts and the admin's curl; the server's caps, not the script, bound the spend of a run
  the script cannot reach.
- **No spend endpoint exists.** The day's spend is only in the VM's database (query in section F).
- The cost on the PASS line is `Run.cost_usd` only; the reporter's Super call (about $0.004) is in the hosted day ledger, not in it. There
  is no local DB to total as `e2e_agent.py` does.
