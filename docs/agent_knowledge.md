# Orchapod Agent knowledge (the planner reads this at request time — keep it current)

## Node catalog
Source of truth: `NODE_REGISTRY` in packages/workflow_schema/models.py. On every request the planner (apps/api/agent/planner.py) appends each row not marked `hidden` to its prompt, after this file: inputs JSON Schema → outputs, runtime (cpu | gpu | api), and typical cost and time from its `TYPICAL` table. Estimates price synth-distilabel, web-research, judge-eval and vllm-serve (its endpoint bills from creation: about 5 minutes to start, then keep_alive_min) from their inputs and `orchapod.prices.PRICES`, and tf-finetune from its trained tokens (synth-distilabel's rows × data-prep's train_split × about 250 tokens a row × epochs) once PRICES has its base model's fine-tune price; until then it assumes its typical $0.50, with a warning. Canonical plans: apps/api/agent/templates/*.json.

## Constraints every plan must respect
- The run report is not a node: the Orchapod Agent writes it from the run's own results after the run ends. Never plan a node for a report, summary or write-up; no node runs after judge-eval.
- Token Factory fine-tunes Llama 3.1 (8B, 70B), Llama 3.2 (1B, 3B), Llama 3.3 70B, Qwen3 and Qwen2.5, gpt-oss, DeepSeek, Gemma 4. It does **not** fine-tune Nemotron.
- Deploying a Token Factory fine-tune: per-token LoRA deploy is retired (POST /v0/models → 410, 2026-10-22). Never plan tf-deploy. Serve the adapter with vllm-serve: `model` = the tf-finetune base (Meta's bases are gated on Hugging Face: HF_TOKEN), `lora_adapter` from tf-finetune; judge-eval compares vllm-serve's `base_model_ref` and `model_ref`.
- A plan that trains with unsloth-train (an H100 Serverless Job) and serves with vllm-serve sets vllm-serve's `keep_alive_min` to 15 and unsloth-train's `merge` to false: the endpoint bills from its creation, and that keeps the plan under the $3 run cap (vllm-serve refuses to start when its worst case, 15 min of start plus keep_alive_min, is above what the run has left).
- Student choice: when the intent names no model, train NVIDIA's student, nvidia/Llama-3.1-Nemotron-Nano-8B-v1 (open weights, not gated), with unsloth-train on an AI Cloud Serverless Job, and serve it with vllm-serve: `model` = the student, `lora_adapter` from unsloth-train (base and tuned on one endpoint, so judge-eval compares `base_model_ref` and `model_ref`). Use tf-finetune (a Token Factory fine-tune) only when the intent names a model Token Factory fine-tunes, such as Llama 3B.
- Nemotron students train on AI Cloud (Serverless Job) and serve from a Serverless Endpoint. Default student: nvidia/Llama-3.1-Nemotron-Nano-8B-v1 (tested: trains, merges and serves on one GPU; fits an L40S). nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16 also works but needs an 80 GB GPU and is about 12× slower to train.
- Quantize: GGUF runs on CPU; AWQ needs a GPU job. To judge a LoRA against its base on CPU (quantize with `lora_adapter`), `base_model_ref` and `tuned_model_ref` are both quantize's `gguf_file`, `tuned_lora` is its `gguf_lora`, and `keep_f16` is false: `gguf_f16` is the baseline only for one model's quantization loss (intent #3), and an 8B f16 (16 GB) does not fit the CPU eval.
- Every plan states a cost and time estimate. Caps: $3 per run, $15 per day, Serverless Job timeout 1 h.

## Maths shortlist (intent #3)
Rule: at most 2B parameters and a short chain of thought, because judge-eval answers with llama.cpp on CPU (measured 2026-10-21 on an M1 Pro's Docker VM under load: 50 GSM8K rows answered by both the f16 and the q4_k_m GGUF of Qwen2.5-Math-1.5B in 18 min, about 305 tokens per answer). Parameter counts and licences are from the Hugging Face API on 2026-10-21.
| Model | Params | Licence | Why |
| --- | --- | --- | --- |
| Qwen/Qwen2.5-Math-1.5B-Instruct (default) | 1.54B | Apache-2.0, not gated | Maths-tuned; its chat template asks for step-by-step reasoning with the answer in \boxed{}, so answers are short and exact match reads them. Proven here: q4_k_m 0.99 GB from a 3.09 GB f16 GGUF, and the q4 answered GSM8K test item 1 correctly. |
| nvidia/AceMath-1.5B-Instruct | 1.78B | CC-BY-NC-4.0 (non-commercial) | NVIDIA's maths model on the Qwen2.5-Math base, same short boxed answers; choose it for an NVIDIA-only story when non-commercial use is acceptable. |

Not on the list: DeepSeek-R1-Distill-Qwen-1.5B (MIT) and nvidia/OpenMath-Nemotron-1.5B (CC-BY-4.0) are long-reasoning models for competition maths (OpenMath-Nemotron's card example allows 4,096 new tokens), too slow on CPU; Qwen/Qwen3-1.7B is 2.03B and thinks at length by default; SmolLM2-1.7B-Instruct, Llama-3.2-1B-Instruct and gemma-2-2b-it (2.6B) are general models, and the last two are gated (HF_TOKEN plus an accepted licence).
