## What `python scripts/e2e_agent.py --intent 2 --max-cost 0.5` does now

`make agent-e2e INTENT=2 MAX_COST=0.5` is the same (`MAX_COST ?= 3` added; `--max-cost "$(MAX_COST)"`).

- **Refused before anything starts** (argparse, exit 2, one line, no key value in it): no `--max-cost`; one at or under 0, or nan; one over the $3 run cap ("caps a run at $3"); no or blank `--intent` (what make passes when INTENT is unset); NEBIUS_API_KEY unset or blank.
- **The stack** is e2e_demo's `with_stack` (own API, throwaway DB, first free port from 8003, `build_images`, `preflight`), with `real_env(max_cost)` as `api_env`'s `extra`: ORCHAPOD_MAX_RUN_USD = ORCHAPOD_MAX_DAY_USD = the `--max-cost` value, ORCHAPOD_ANON_SCALE = 1, STUB removed, NEBIUS_BASE_URL removed (a shell's base URL cannot receive the key), and of `e2e_demo.PAID` only NEBIUS_API_KEY, TAVILY_API_KEY and HF_TOKEN, each when non-blank. VASTAI, RunPod, Anthropic, OpenAI, NEBIUS_PROJECT_ID, NEBIUS_IAM_TOKEN and ORCHAPOD_ENDPOINT_TOKEN stay dropped.
- **Refused before POST /agent/run** (a FAIL line each, exit 1; `preflight` and `build_images` are not reached): a plan error; an estimate over `--max-cost`; a node that rents a GPU (runtime gpu or `rents_gpu` in NODE_REGISTRY, read from the real registry); a node whose key is unset (`NEEDS_KEY = {"web-research": "TAVILY_API_KEY"}`).
- **The run**: the client waits 600 s per call (the live planner is up to 300 s a call with repairs; the stack's 30 s would abandon a plan the API goes on to bill); it polls the report every 2 s until `ready` (a finished run whose report is still being written keeps being polled), within 30 minutes (`demo.LIMIT_S = 1800`, set by `main`).
- **Checks** (the stub's, reused): `demo.check_run` (every node's contract artifacts and a cost_json), `check_report` (intent, ready, names the plan), `demo.fetch_dataset` (downloads, rows with exactly the schema's fields), keep_f16, eval_summary. Added for a real run: `0 < cost_usd <= --max-cost` ("a real run that cost $0 called nothing"); a structured synth node's dataset holds at least 90 % of its `n_samples` (model default 1000 when the plan omits it; integer arithmetic, so 450 of 500 passes and 449 fails); judge-eval's eval_summary says `stub` false. The canonical shape rule (#2 trains nothing, ...) applies to a real plan too.
- **Output**: the stub's PASS/FAIL line (run id, wall time, cost, estimate, report chars), then the report's first 5 lines. A real FAIL line also carries cost and estimate; the report head is shown on a FAIL too. The stub's output is unchanged (pinned by a test).
